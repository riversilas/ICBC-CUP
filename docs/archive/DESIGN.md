## 0. 三条不可违背的硬约束

在讨论任何美学之前，这三条优先。**违反它们的"更好看"一律否决。**

| # | 约束 | 原因 |
|---|---|---|
| 1 | **零第三方依赖、零网络请求** | 这是项目的核心卖点（`requirements.txt` 为空、离线可跑）。**不得引入任何 webfont、CDN、动画库、图标库**。所有图形用 inline SVG，所有纹理用 inline data-URI。 |
| 2 | **中文优先，Windows/Edge 环境** | 主要运行环境是 Windows + Edge，界面全中文。字体策略必须围绕这个事实，而不是围绕设计潮流。 |
| 3 | **数字即事实，不可为了好看而遮挡或重排** | 这是给银行看的合规工具。任何"为了视觉平衡而隐藏数据、四舍五入掉关键位、或者把表格改成卡片"的改动都**否决**。 |

## 1. 视觉主题与氛围

**一句话**：一间光线充足、材料考究的**审计事务所**——克制、精确、有分量，但绝不冷硬。

| 维度 | 取值 | 说明 |
|---|---|---|
| 密度 Density | **5 / 10**（日常工具档） | 数据表格要紧凑，营销页面要透气。**两种密度并存是刻意的**，不要统一。 |
| 变化度 Variance | **6 / 10**（偏不对称） | 落地页允许破对称；工作台必须对齐、可预测。 |
| 动效 Motion | **5 / 10**（流畅 CSS） | 有质感但不表演。**任何一次动效都不得超过 760ms**。 |

**氛围的关键词**：墨绿、米白、哑金、纸张、刻度、复算。

**氛围的反面（要避免的观感）**：科技蓝、渐变紫、玻璃拟态堆砌、仪表盘大屏、加密货币风。

## 2. 色彩体系与角色

### 2.1 主色（品牌墨绿系）

| 名称 | 色值 | 用途 |
|---|---|---|
| **深墨绿 Deep** | `#123e30` | 落地页 hero 底、品牌栏底。**只用于大面积暗底，不用于文字。** |
| **正文墨绿 Ink** | `#183d31` | 标题、强调文字。比纯黑柔和，保持色相统一。 |
| **主绿 Primary** | `#1f6b4a` | 唯一的行动色：主按钮、链接、数据高亮、焦点环。 |
| **浅绿 Soft** | `#eaf1e6` | 成功态底、选中行底。 |
| **极浅绿 Tint** | `#f2f7ee` | 表格 hover 底、`code` 底。 |

### 2.2 点缀色（哑金）

| 名称 | 色值 | 用途 |
|---|---|---|
| **哑金 Gold** | `#e8ce91` | 深底上的 CTA、hero 高亮词。 |
| **深金 Gold Deep** | `#b8923f` | 浅底上的金色细节：步骤条当前项下划线、`eyebrow` 圆点。 |
| **金底 Gold Soft** | `#fdf6e4` | 提示块（`.notice`）底色。 |

> **⚠️ 关于「双强调色」的偏离**：通用设计规范要求"最多一个强调色"。
> 本项目**刻意保留绿 + 金两个**，因为金色在这个语境里**不是竞争性强调色，而是材质**——
> 它承担"印章/凭证/权威"的语义（存证、评级、当前步骤），且**从不与主绿争夺同一个层级**：
> 深底上用金，浅底上用绿；按钮用绿，分割与小标记用金。
> **执行规则：任何单一元素上不得同时出现绿和金做主色**（例外：盾形 logo 的渐变描边）。

### 2.3 中性色（全部带绿相，绝不混入暖灰）

| 名称 | 色值 | 用途 |
|---|---|---|
| **背景 Canvas** | `#f7f9f5` | 页面底 |
| **卡面 Surface** | `#ffffff` | 卡片 |
| **分割 Line** | `#dfe6dc` | 主边框 |
| **浅分割 Line Soft** | `#eef2ec` | 表格行线、虚线分割 |
| **正文 Ink** | `#1c2b24` | 正文 |
| **次要 Muted** | `#66786d` | 说明文字、标签 |
| **三级 Muted-2** | `#8a9a90` | 时间戳、元信息 |

> **铁律**：所有中性色**必须带绿相**（`R < G` 且 `B` 介于两者之间）。
> **禁止引入暖灰（红相）或纯灰（R=G=B）**——一旦混入，整页会立刻显出"拼装感"。
> 新增中性色时，用上面任一色值微调明度，不要新调一个色相。

### 2.4 语义色

| 名称 | 色值 | 用途 |
|---|---|---|
| **正向 OK** | `#177245` | 下降箭头、通过、达标 |
| **警示 Warn** | `#9a6b00` | 数据待补、注意 |
| **负向 Bad** | `#b4453a` | 上升箭头、失败、篡改检出 |
| **信息 Info** | `#2c5b8f` | 中性标签 |

> 语义色的饱和度**刻意压低**（都在 60–70% 区间）。
> **禁止使用纯红 `#ff0000` / 纯绿 `#00ff00` / 霓虹色**——它们在这个墨绿语境里会显得廉价。

### 2.5 色彩使用配比（重要）

整个界面应按以下大致比例分布，**这是"看起来高级"的最大单一因素**：

```
整页视觉面积 ≈ 70% 米白/白（背景与卡面）
             ≈ 20% 墨绿（文字、按钮、品牌栏、hero）
             ≈  8% 中性分割与灰阶
             ≈  2% 金（点缀）
```

**违反配比的典型症状**：金色用得过多 → 显俗；绿色面积过大 → 显压抑；空白不足 → 显廉价。

## 3. 字体与排版

### 3.1 字体栈（**刻意不使用 webfont**）

```css
--font: "Segoe UI Variable Text", "Segoe UI", -apple-system, "Helvetica Neue",
        "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-display: "Segoe UI Variable Display", "Segoe UI", -apple-system, ...;
--mono: "Cascadia Mono", "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
```

> **⚠️ 偏离说明（给 agent 的明确指令）**：
> 通用高端设计规范要求使用 `Geist` / `Outfit` / `Satoshi` 等具有个性的 webfont，
> 并**明令禁用 `Inter`**。本项目**不采用该指令**，理由见 §0 硬约束 1：
> 加载 webfont 需要网络请求，而本项目在比赛现场可能**无网**，字体加载失败会直接
> 拖垮首屏观感。用系统字体栈是**权衡后的正确选择**，不是偷懒。
>
> **执行规则**：
> - **不要**添加任何 `@font-face` 或字体 CDN 链接。
> - **不要**在字体栈里加 `Inter`（它在 Windows 上通常未安装，写了也白写，只会让栈显得不可信）。
> - 需要"个性"时，**通过字重、字距、字号的对比来制造**，而不是通过换字体。

### 3.2 排版规则

| 场景 | 规格 | 要点 |
|---|---|---|
| 落地页主标题 | `clamp(34px, 4.2vw, 58px)`，`weight 750`，`letter-spacing −2.2px`，`line-height 1.24` | 大字号**必须负字距**，否则中文会散开 |
| 章节标题 `.h-section` | `clamp(23px, 2.5vw, 32px)`，`weight 700`，`letter-spacing −0.9px` | |
| 卡片标题 `.card h2` | `16.5px` / `weight 700` / `letter-spacing −0.3px` | 字号小，负字距要收敛 |
| 正文 | `14px` / `line-height 1.7` | 段落 `max-width: 65ch` |
| 说明文字 `.muted` | `12px` / `--muted` | |
| 眉标 `.eyebrow` | `10.5px` / `weight 700` / `letter-spacing 2.1px` / **大写** | 全站唯一允许用大字距+全大写的地方 |
| 代码 / 摘要 | `--mono` / `12.5px` | |

**四条硬性规则**：

1. **数字必须等宽**：所有数据类文本加 `font-variant-numeric: tabular-nums`。
   否则数字一变化，列宽就抖动、上下行对不齐。（见 `theme.css` 的 `.num` 规则组）
2. **标题用 `--font-display`、正文用 `--font`**：让大字号拿到更紧的默认字距。
3. **负字距只给大字号**：`≥20px` 用负字距，`<14px` 用 `0` 或正字距。反过来用会显得挤。
4. **避免孤行**：长标题加 `text-wrap: balance`，长段落加 `text-wrap: pretty`。

## 4. 形状与圆角体系

**圆角不是随手定的，它编码层级。** 越靠内的元素圆角越小，越靠外的容器圆角越大。

| Token | 值 | 用在哪 | 理由 |
|---|---|---|---|
| `--r-sm` | **8px** | 按钮、输入框、小标签底 | 交互元素要"利落"，圆角过大会显软 |
| `--r` | **14px** | KPI 卡、公式块、报告框、引言块 | 内容容器的基准 |
| `--r-lg` | **20px** | 最外层卡片 `.card` | 最大容器，最柔 |
| *(局部)* | **4px** | `.intro` / `.notice` 的左侧强调边 | 强调边必须"硬"，与主体的柔形成对比 |
| *(局部)* | **20px** | `.tag` 胶囊标签 | 唯一允许全圆角的地方（小尺寸下的胶囊） |
| *(局部)* | **50%** | `eyebrow` 圆点 | |

**规则**：

- **禁止全站统一圆角**（"所有东西都 12px"是最典型的模板感来源）。必须按上表分层。
- **嵌套时内层必须小于外层**：20px 卡片里的按钮用 8px，不要也用 20px。
- `.intro` / `.notice` / `.verdict` 用**不对称圆角** `4px 14px 14px 4px`：左侧贴边、
  右侧柔化，让"强调边"读起来像书页的书脊。
- 深底区域（hero、品牌栏）的圆角一律 **0**——它是"画面"，不是"卡片"。

## 5. 阴影与光源

**全站只允许一个光源方向：正上方。** 所有阴影必须暗示光从上往下照。

| Token | 值 | 用途 |
|---|---|---|
| `--shadow-sm` | `0 1px 2px #123e300a, 0 4px 14px -8px #123e3018` | 悬浮提示、小浮层 |
| `--shadow` | `0 18px 45px -32px #244c3060, 0 2px 6px #123e300a` | 卡片默认 |
| `--shadow-lg` | `0 30px 70px -40px #244c3070` | 强调卡、弹出层 |

**三条规则**：

1. **阴影必须染色**：色值一律取自品牌绿的深色（`#123e30` / `#244c30`），
   **禁止 `rgba(0,0,0,.1)` 这类中性黑阴影**——在黑阴影下，米白底会发灰。
2. **大扩散 + 低透明度**：`45px` 扩散配 `-32px` 收缩，得到"贴地"的柔和感；
   小尺寸模糊 + 高透明度会立刻显廉价。
3. **卡片额外加顶部内高光**：`inset 0 1px 0 #ffffffd9`，模拟材质边缘受光。
   这是让卡片"有厚度"而不是"贴纸"的关键。

## 6. 布局与视觉分布

### 6.1 容器

| 场景 | max-width | 内边距 |
|---|---|---|
| 工作台 `.wrap` | `1200px` | `26px 22px 64px` |
| 落地页章节 | `1140px` | `clamp` 式响应 |
| 收尾区 `.closing` | `920px` | — |

居中用 `margin: 0 auto`。**禁止内容在宽屏上通栏铺开。**

### 6.2 纵向节奏

- 区块间距：`78–86px`（落地页）/ `18px`（工作台卡片之间）。**两种密度并存是刻意的。**
- **对称内边距是错的**：底部内边距**必须略大于**顶部（视觉重心偏上才稳）。
  例：`.wrap` 是 `26px` 顶 / `64px` 底。
- 宁可多留白。**"这块还能再塞点东西"的时候，就是该停的时候。**

### 6.3 破对称规则（落地页专属）

**禁止三栏等宽卡片**（`grid-template-columns: repeat(3, 1fr)`）——这是最强的模板感信号。
`values` 区块已经改成 **5 / 4 / 3 的 12 栅格收窄节奏 + 逐级下沉 34px/68px**，
形成「主 → 次 → 补」的阅读层级。**新增任何三栏区块时，必须沿用同样的不对称逻辑。**

工作台（`app.html`）**不适用**破对称——它是工具，对齐和可预测性优先。

### 6.4 全屏区域

- 用 `min-height: 100svh`，**不要用 `100vh`**（iOS Safari 地址栏会导致跳动）。
- 已经改为满屏的 hero 需要给用户"还有下文"的线索。**禁止使用"scroll to explore"文案、
  跳动箭头、下滑手式图标**——这些是无信息量的装饰。
  本项目用**顶部 2px 阅读进度条**（纯 CSS `animation-timeline: scroll()` 驱动）替代。

### 6.5 表格

- 表头：`11px` / `weight 700` / `letter-spacing .5px` / `--muted` / 浅底 `#fafcf8`。
- 行线只用**下边框**，最后一行去掉。
- 可点行：`cursor: pointer` + hover 变 `--green-tint` + 首列右移 `3px`。
- **表格不得改成卡片流。** 银行用户需要横向比对，卡片会破坏列的语义。

## 7. 动效与交互（`motion.css`）—— ⚠️ 待实现规范，当前文件不存在

> 本节描述**应该怎么做**，不代表代码里已经有。照此新建 `motion.css` 时，
> 务必先读第 6 行下方关于回退原因的两条说明。

### 7.1 时长为 4 档令牌，禁止散写

```css
--dur-1: 120ms;   /* 按压、hover 微反馈 */
--dur-2: 220ms;   /* 常规状态切换 */
--dur-3: 420ms;   /* 内容入场 */
--dur-4: 760ms;   /* 数据可视化绘制 */
```

**禁止出现 `.18s` / `.5s` 这类散写时长。**

### 7.2 缓动只有两条

```css
--ease-out:    cubic-bezier(.22, .61, .36, 1);   /* 减速，用于"进入/落定" */
--ease-spring: cubic-bezier(.34, 1.32, .64, 1);  /* 轻微回弹，用于"可交互元素" */
```

**禁止 `linear`**（唯一例外：滚动驱动的进度条必须严格 1:1，见 §7.6）。

### 7.3 只动 `transform` 与 `opacity`

**绝对禁止**动画 `top` / `left` / `width` / `height`——它们触发逐帧重排，会在低配演示机上掉帧。

**唯一例外**：`.bar > i` 的进度条动画 `width`。元素仅 7px 高，重排成本可忽略；
用 `scaleX` 反而会压扁 4px 圆角，更难看出。**这是经过权衡的例外，不要推广到别处。**

### 7.4 错位入场（stagger）—— 绝不能整块同时出现

- 卡片序列：**每项延迟 55ms**（`.view.active > *` 的 nth-child 规则）。
- KPI 网格：**50ms** 一档，起始 `80ms`。
- 表格行：**50ms** 一档，起始 `40ms`。
- 三栏价值卡：**70ms** 一档。

**判断标准**：如果一整屏内容同时"啪"地出现，就是错的。

### 7.5 动效清单（每个元素该配什么）

| 元素 | 动效 | 时长 / 缓动 |
|---|---|---|
| 按钮 hover | `translateY(-1px)` + 阴影增强 | `--dur-2` / `--ease-out` |
| 按钮 press | `translateY(1px) scale(.985)` + 收掉抬升阴影 | `--dur-1` |
| 卡片 hover | 无（工作台卡片不悬浮） | — |
| KPI hover | `translateY(-2px)` + 阴影 | `--dur-2` / `--ease-spring` |
| 步骤条当前项 | 金色下划线从中间向两侧展开 | `--dur-3` / `--ease-out` |
| 表格行 hover | 背景变色 + 首列右移 3px | `--dur-2` |
| 链接 hover | 下划线从左往右"长"出来（`background-size` 0→100%） | `--dur-2` |
| 雷达图 | 整图从 `scale(.94)` 展开 | `--dur-4` / `--ease-out` |
| 进度条 | `width` 从 0 长到目标值 | `--dur-4` / `--ease-out` |
| KPI 数字 | 从 0 滚动到目标值（`easeOutCubic`，760ms） | JS `countUp()` |
| 骨架屏 | 渐变 `background-position` 循环 | `1.4s linear infinite` |
| 落地页章节 | 滚动进入视口时上浮（CSS `view()` 时间轴） | `--dur-4` / `--ease-out` |

### 7.6 三条安全规则（**违反会导致内容隐形**）

1. **动效层只加动效，不承担"让内容可见"的职责。**
   `theme.css` 里 `.view.active` 刻意**不写** `animation`。
   → `motion.css` 加载失败时，内容照常显示，只是没有动画。**保持这个设计。**

2. **使用 `animation-fill-mode: both` 的入场动画，必须在 `prefers-reduced-motion`
   下显式复位。** 不能只靠 `animation-duration: .01ms` 兜底——
   **滚动时间轴（`scroll()` / `view()`）的进度由滚动位置驱动**，
   把时长压到 0 并不能保证它落到终态，元素可能停在 `opacity: 0`。
   → 见 `motion.css` §0 的完整复位名单，**新增动画时必须把选择器加进去**。

3. **JS 增强必须可失败。** `countUp()` 在 `prefers-reduced-motion`、
   非数字、元素缺失时**一律直接落终值**，绝不留下空值。
   快速切换企业时用 `cancelAnimationFrame` 取消上一轮。

## 8. 响应式

| 断点 | 行为 |
|---|---|
| `≤ 980px` | 落地页 `.chapter` 由左右两栏塌成单栏 |
| `≤ 820px` | 工作台卡片内边距收窄；`.hero-art` 隐藏；`.hide-sm` 列隐藏；**12 栅格必须同时清掉 span 与下沉偏移** |

**规则**：

- 任何多栏布局在 `≤820px` **必须塌成单栏**，无例外。
- **不得出现横向滚动**。
- 触控目标 `≥44px`。
- 标题用 `clamp()` 缩放；正文最小 `14px`。
- 章节间距用 `clamp(3rem, 8vw, 6rem)` 比例收缩。

---

## 9. 无障碍（不可省略，不是可选项）

1. **焦点环必须有**：`:focus-visible` 用 `outline: 2px solid var(--green); outline-offset: 2px`。
   用 `outline` 而非 `box-shadow`，避免与卡片/按钮自身阴影互相覆盖。
2. **尊重 `prefers-reduced-motion`**：见 §7.6 规则 2。
3. **语义化标签**：用 `<nav>` / `<main>` / `<section>` / `<article>`，不要 div 汤。
4. **打印样式**：`.stepbar` / `.navbtns` / `.brand-back` 隐藏，卡片去阴影去边框。
5. **颜色不是唯一的信息载体**：涨跌同时用箭头 `▲▼` 和颜色；可信度用**词语**不用字母。

## 10. 禁止清单（Anti-Patterns）

以下每一条都会立刻让界面显得"模板化"或"廉价"。**发现即改。**

### 视觉

- ❌ 纯黑 `#000000` 做背景或文字色 → 用 `#183d31` / `#1c2b24`
- ❌ 中性黑阴影 `rgba(0,0,0,.1)` → 用染色阴影
- ❌ 紫/蓝"AI 渐变"、霓虹发光、外发光按钮
- ❌ 高饱和强调色（饱和度 > 80%）
- ❌ 同一元素上绿色和金色同时做主色
- ❌ 暖灰与冷灰混用
- ❌ 全站统一圆角
- ❌ 完全平直无纹理的纯色大面（已有 `--grain` 噪点层，opacity `.03`，**不要调高**）
- ❌ 大面积纯平渐变（要渐变就用径向 + 噪点打破均匀）

### 布局

- ❌ 三栏等宽卡片（`repeat(3, 1fr)`）
- ❌ 全部居中的对称 hero
- ❌ `height: 100vh`（用 `100svh`）
- ❌ 用 flex 百分比 `calc()` 做多栏（用 CSS Grid）
- ❌ 无 `max-width` 约束的通栏内容
- ❌ 表格改成卡片流

### 动效

- ❌ 动画 `top` / `left` / `width` / `height`（唯一例外见 §7.3）
- ❌ 散写时长（`.3s`、`500ms`）→ 用 `--dur-*` 令牌
- ❌ `linear` 缓动（滚动进度条除外）
- ❌ 一次动效超过 760ms
- ❌ 整屏内容同时出现（必须 stagger）
- ❌ 无限循环的装饰性动画（跳动箭头、呼吸光晕）
- ❌ 自定义鼠标指针

### 内容

- ❌ emoji 当图标用
- ❌ "Scroll to explore" / "向下滑动" / 跳动箭头 / 下滑手式
- ❌ AI 文案腔（"赋能"、"无缝"、"一站式"、"全新升级"）
- ❌ 占位假名（"张三"、"某某公司"）与假整数（`99.99%`、`50%`）→ 用真实披露值
- ❌ 成功提示带感叹号
- ❌ "哎呀！"式错误提示 → 直接说"存证查找失败"

## 11. 有理由的偏离（Deviations from generic guidance）

给 agent 的明确指令：**以下偏离是深思熟虑的，不要"修正"它们。**

| 通用规范说 | 本项目做法 | 理由 |
|---|---|---|
| 用有个性的 webfont，禁用 `Inter` | **用系统字体栈，且不写 `Inter`** | 零网络请求是硬约束；比赛现场可能无网 |
| 最多一个强调色 | **绿 + 金** | 金色是"材质/印章"语义，非竞争性强调色；从不与主绿争同一层级 |
| 卡片要"border + shadow + 白底" | **保留边框，但加顶部内高光** | 表格型工具需要清晰边界；高光提供材质厚度 |
| 不要用 `Inter` 以外也不要用系统字体 | 见上 | — |
| 优先图片/纹理填充空旷区块 | **用雷达骨架 SVG + 噪点，不用照片** | 这是数据工具，放 stock 照片会削弱可信度 |

## 12. 落地检查清单（改完 UI 后逐条自查）

**视觉**
- [ ] 新颜色是否属于既有色系（墨绿/哑金/带绿相中性）？
- [ ] 阴影是否染色、光源是否朝上？
- [ ] 圆角是否按层级变化，而非全站统一？
- [ ] 绿:金:中性 的比例是否仍接近 20:2:78？

**布局**
- [ ] 是否所有区块都有 `max-width` 约束？
- [ ] 是否没有出现三栏等宽卡片？
- [ ] 底部内边距是否 ≥ 顶部内边距？
- [ ] `≤820px` 是否塌成单栏且无横向滚动？

**动效**
- [ ] 时长是否全部来自 `--dur-*` 令牌？
- [ ] 是否只动了 `transform` / `opacity`？
- [ ] 列表是否 stagger？
- [ ] **是否已把新动画的选择器加入 `motion.css` §0 的 reduced-motion 复位名单？**（最容易漏）
- [ ] 关掉 `motion.css` 后，内容是否仍完整可见？

**无障碍**
- [ ] 新交互元素是否有 `:focus-visible` 样式？
- [ ] 信息是否不只靠颜色传达？
- [ ] 是否用了语义化标签？

**总纲**
- [ ] 是否引入了任何外部请求？（**必须为"否"**）
- [ ] 数据是否仍然完整、未被视觉处理遮挡或改写？
