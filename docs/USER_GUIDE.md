# 绿碳链证 · 产品介绍与图文使用指南

> 修订日期：2026-10-18。适用入口为仓库根目录 `app.py`。截图来自修订后的真实页面，使用隔离演示账本，不含用户银行材料。

## 一、这是什么程序

绿碳链证是一套在本机浏览器中运行的电力企业碳数据演示工具。它把散落在披露索引、附件和人工补充中的信息组织成可阅读的企业画像，再把某一次确定的内容登记为带版本、摘要和前后关联的材料包，方便展示、复算、交接与核对。

它解决的是三个问题：**数字从哪里来、怎么算出来、交来的材料是不是当时登记的那个版本。** 它不替企业保证数据真实，不给企业综合评级，不自动建议贷款或利率，也不把本地哈希链冒充独立公共区块链。

### 可以直接使用的介绍文案

“绿碳链证以电力企业的直接排放、间接排放和发电量为基础，让碳数据从一组数字变成可解释、可追溯、可核对的材料。使用者可以查看排放构成与年度变化、检查来源与核算方法、补充投入和计划材料，再生成带版本的参考报告。报告登记后，接收方可用摘要找到对应记录，并提交原始登记包进行材料比对。系统明确区分原值、推导值、演示假设与未核验材料，保留缺失项和方法边界，不把图形面积包装为绩效分数，也不把材料一致解释成真实性认证。”

### 适合谁

| 使用者 | 主要用途 | 不能替代的工作 |
|---|---|---|
| 项目演示/比赛团队 | 展示数据→复算→登记→核对的闭环 | 真实银行生产系统验收 |
| 数据整理人员 | 对照原值、单位、来源与补充修订 | 原报告逐页核实 |
| 银行业务交流人员 | 查看资料完整性和待核查项 | 财务征信、授信与合规审批 |
| 开发或其他AI | 复现流程和理解输入边界 | 自行猜测缺失数据 |

## 二、安装与启动

### Windows

1. 下载当前仓库 `main` 的完整源码并解压到有读写权限的目录。
2. 安装 Python 3.10+，包含 `py` 启动器；重新打开终端运行 `py --version` 确认。
3. 双击根目录 `启动.bat`。脚本检查已有虚拟环境是否能执行；坏环境会改名保留，再创建本机新环境。依赖缺失或清单变化时才安装。
4. 浏览器访问 **http://127.0.0.1:8910/**。保持服务终端开启，按 Control+C 停止。

### macOS

1. Finder解压标准ZIP，不要在压缩包内运行。
2. 安装适合本机芯片的Python 3.10+。
3. 终端输入 `cd `，把项目文件夹拖入终端后回车，再执行 `bash start.command`。
4. 首次联网创建 `.venv-macos` 并安装依赖。若8910占用，执行 `PORT=8911 bash start.command`。

**不要复制其他电脑的 `.venv`，Mac不能运行Windows的exe或bat。** 首次依赖安装与外部来源链接需要网络。源码包不自带Python。实体Mac/全新Windows机器本次未实测，排障见 [MACOS_GUIDANCE.md](MACOS_GUIDANCE.md)。

手动启动：先执行 `python -m pip install -r requirements.txt`，再执行 `python app.py --port 8910`。Windows可用 `py` 替代 `python`。

## 三、五分钟完成四步闭环

### 第一步：选择企业

进入工作台后，可以点击“开始示例”，直接载入大唐发电；也可选择企业卡片。确认企业代码、年度与数据性质，不要把演示年度当成已确认的披露年度。

![① 点击开始示例](guide-images/01-select-annotated.png)

### 第二步：先读原值，再读图

画像上方显示scope1、scope2、总量、发电量和排放强度。scope1是直接排放，scope2是外购能源相关间接排放。总量由二者相加，强度由总量和发电量推导。它们是不同单位的原值，不应直接相加成分数。

![② 先核对原值与单位](guide-images/02-profile-annotated.png)

以大唐2024附件数据为例：scope1为210,817,900 tCO2，scope2为107,600 tCO2，发电量285,153 GWh，总量210,925,500 tCO2，强度约739.69 kgCO2/MWh。界面可按一位小数显示，登记内容保留计算精度。

展开“查看排放构成与相对变化”，可以看到排放构成和四轴变化图。

![③ 四轴变化图阅读方式](guide-images/03-radar-annotated.png)

- 四个轴：scope1、scope2、发电量、排放强度；前期=100，本期指数=本期÷前期×100。
- 例如107表示增长约7%，不是107分；63表示下降约37%，不是不及格。
- 排放轴向内表示减排方向，向外表示增排方向，仍须核对边界及产出；发电量只表示规模变化，不判好坏。
- 图形面积不能排名，也不能比较两家企业的绝对排放强度。要比较739.69与287.71，应看原值与单位，不看相对图面积。
- 图上限200；超过时标实际指数。缺项不补零，缺可比前期不画跨期图。
- “假设同口径复算”不等于已核实可比；组织边界、气体范围或scope2核算方法不一致时，不能直接据图作减排结论。

继续展开“历年数据”“核算方法”“数据来源”，查看原值表、公式和来源线索。检索链接只帮助找到报告，不表示程序已下载或核验PDF。

### 可选：补充材料、投入、计划与银行记录

展开“数据复核 / 补充”，填写本次修订原因，再勾选需要的分区。未勾选分区保持不变。

- **材料**：标题、年度、HTTP(S)来源链接，尽量补页码/定位。
- **投入**：金额、同年度资本支出、分类和依据；环保投入不能自动当作低碳资本开支。
- **计划**：目标、实际、单位、技术及来源；执行状态不能代替目标达成证明。
- **银行记录**：金额、期限及考核指标，只是待核查输入，不自动审批。

先“预览本次补充”，再“保存补充记录”。JSON导入只进行预览，不自动保存。遇到修订冲突时读取最新修订，手动核对合并；不要覆盖别人新保存的内容。保存后原报告不变，需要生成新版本报告。

### 第三步：生成报告与保留登记包

确认企业和内容后进入第三步，点击生成按钮。报告把当时的画像、补充修订、来源、限制和版本信息登记为快照，而不是每次查看时从最新API拼装。

![④ 生成版本化报告](guide-images/04-generate-annotated.png)

- 报告显示企业/年度、报告版本、登记摘要和本地链回执。
- 报告三轴图只画scope1、scope2、发电量；总量与强度仍保留在原值表。这样减少派生量重复占轴，不是删掉数据。
- 滚动到报告底部，可以打印或下载“原始登记包JSON”。打印可由浏览器选择保存PDF。
- **请同时保留JSON与完整摘要。** 打印PDF用于阅读，JSON用于本程序的材料比对；PDF字节本身不是这里的核验对象。
- 未保存的表单不进入报告；同一内容可复用现有登记，不必每次产生重复版本。

### 第四步：查询记录与比较提交材料

从报告进入第四步会带入登记摘要。也可直接从首页进入查验，不必先生成新报告。

1. 输入完整64位登记摘要，点击“查询记录”：只能确认本机账本是否有该记录。
2. 选择第三步下载的原始登记包JSON，点击“比较提交材料”。
3. 分别读结果，不要把几种状态合成“认证通过”。

![⑤ 读取材料匹配等独立结果](guide-images/05-verify-annotated.png)

| 结果项 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 登记存在 | 本机有对应记录 | 企业填报真实 |
| 提交材料匹配 | 提交的登记内容与所登记版本一致 | PDF原文已核实 |
| 链内部一致 | 本地记录关联和摘要自洽 | 有独立节点或不可全链重算 |
| 当前/历史版本 | 是否已有替代登记版本 | 历史版本无价值 |
| 外部锚定未实施 | 当前无独立外部锚定证据 | 已完成公共链确认 |

换一台电脑核验时，必须具备对应的登记记录；源码仓库不包含你本机新生成的私有操作账本。链实验只演示关联机制，不应被讲成现实攻击测评。

## 四、演示讲解顺序（约3分钟）

1. 30秒：说明这是材料可追溯和复算工具，而不是评分/授信系统。
2. 45秒：选大唐，指原值与来源，解释总量和强度公式。
3. 45秒：展开四轴图，指出100基线及排放方向，强调面积不排名。
4. 30秒：生成报告，展示版本、摘要和JSON下载。
5. 30秒：提交JSON，分别解释材料匹配、链一致性与未实施外部锚定。

## 五、常见问题

- **还是旧界面**：确认运行目录和分支，再Ctrl+F5；端口不代表版本，另一个目录也可能监听同一端口。
- **提示端口占用**：改用空闲端口，不结束所有Python/Node进程。
- **没有上一期**：保留单期原值，可以生成报告，不补造前期。
- **为何没有分数和B-**：本次按方案A移除；过去的算法为历史兼容保留，但不是现行页面结论。
- **为何不同地方图轴不同**：首页和第二步四轴描述完整变化；报告三轴避免总量与强度派生信息重复占轴，两处都不评分。
- **找不到记录**：先检查是否为同一台电脑/同一账本、完整摘要及对应版本；联网访问GitHub不会自动同步本机登记数据。
- **上传到GitHub能直接访问网站吗**：不能只靠GitHub Pages运行FastAPI；当前是下载后本机运行的程序。

## 六、备份与隐私

关闭服务后备份 `data/processed/chain_ledger.json` 与 `profile_extensions.sqlite3`，同次备份一起保留。不要提交真实银行材料、数据库、凭据或操作账本到GitHub；源码发行只包括必要输入与代码。不要改写历史登记摘要来适配新版本。

## 七、验证边界

本指南基于Windows Edge自动化真实操作与隔离账本测试，验证了选企业、生成报告、下载JSON、提交材料匹配；没有实体Mac、Safari、全新Windows及打印机人工验收。截图有箭头提示覆层，不属于程序原生界面。方法和历史版本标识保留原意，应用发行版本与报告版本不是同一个号码。
